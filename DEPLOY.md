# Deploying Juma Ops

Production runs on three services:

| Part | Where | Why |
| --- | --- | --- |
| Database + photo storage | Supabase, Mumbai (`ap-south-1`), **Pro plan** | Never pauses; daily backups |
| API (`apps/api`) | Render, Singapore, Starter instance | Always on; `render.yaml` blueprint |
| Web app + salesman PWA (`apps/web`) | Vercel, Mumbai functions (`bom1`) | Next.js host; proxies `/api/v1` to Render |

The browser only ever talks to the Vercel domain. Vercel forwards `/api/v1/*` to Render
(`API_PROXY_URL`), so the login cookie is first-party and works on every phone browser,
including Safari, which blocks cross-site cookies.

Do the steps in order. Budget about an hour.

## 1. Supabase (production project)

Keep the current project as the development/staging database. Production gets its own.

1. Create a new project in **South Asia (Mumbai)**. Save the database password in a password
   manager.
2. Upgrade the organisation to **Pro** before go-live (Settings → Billing). On the free plan a
   project pauses after a week without activity and has no backups. Pro includes daily backups
   (7 days). Point-in-time recovery is an optional add-on.
3. Copy the two pooler connection strings (Connect → ORMs): transaction pooler on port 6543 for
   `DATABASE_URL` and session pooler on port 5432 for `DIRECT_URL`. Add the query string from
   `apps/api/.env.example` to `DATABASE_URL`.
4. Apply the migrations from your machine:

   ```bash
   DIRECT_URL="<session pooler string>" DATABASE_URL="<session pooler string>" pnpm --filter @juma/api db:deploy
   ```

   This includes the migration that turns on row-level security and revokes the anon and
   authenticated grants, so the Supabase data API exposes nothing.
5. Create the private photo bucket (SQL editor), as in the README's **Photo storage** section.
6. Load the base data and the owner's admin login. This loads no demo data:

   ```bash
   SEED_SCOPE=base ADMIN_NAME="<owner name>" ADMIN_PHONE="+91XXXXXXXXXX" ADMIN_PASSWORD="<strong password>" \
     DIRECT_URL="<session pooler string>" DATABASE_URL="<session pooler string>" pnpm --filter @juma/api db:seed
   ```

   It creates the 33 districts, 18 main towns and the allowance policy (edit it under Settings).
   Load the remaining towns with **Settings → Bulk import** (Towns).
   Products, salesmen and partners are added in the app or with **Settings → Bulk import**.
7. Copy the project URL and the **secret** key (Project Settings → API Keys) for the API.

Never run the development seed (without `SEED_SCOPE=base`) or the Playwright tests against
this database. Both create test users, and the tests delete their own data.

## 2. API on Render

1. Render → New → Blueprint, pick this repository. Render reads `render.yaml` and creates the
   `juma-api` service.
2. Fill in the variables marked "sync: false":
   - `DATABASE_URL`, `DIRECT_URL`: from step 1.3
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`: from step 1.7
   - `CORS_ORIGINS`: the Vercel address from step 3. Use a placeholder for now and update it
     after step 3.
   The JWT secrets are generated by Render. Leave them.
3. Deploy. The pre-deploy step runs `prisma migrate deploy` each release. Check that
   `https://<service>.onrender.com/api/v1/health` returns `{"data":{"status":"ok",...}}`.

### Alternative: API on Google Cloud Run

The root `Dockerfile` packages the API alone for Cloud Run, which scales to zero when idle
and runs in Mumbai (`asia-south1`), next to the database.

1. Cloud Run → Deploy container → **Continuously deploy from a repository**, set up with
   Cloud Build: this repository, branch `^main$`, build type **Dockerfile** at `/Dockerfile`.
2. Region `asia-south1`, **Allow public access**, billing **request-based**, minimum
   instances 0.
3. Variables: `NODE_ENV=production`, `TRUST_PROXY_HOPS=2`, `COOKIE_SECURE=true`,
   `COOKIE_SAMESITE=lax`, `SUPABASE_STORAGE_BUCKET=juma-files`, and the same values Render
   asks for in step 2 above. Generate each JWT secret with `openssl rand -base64 48`.
4. Cloud Run has no pre-deploy step: apply new migrations from your machine with
   `pnpm db:deploy` before pushing a schema change.

Use the service URL (`https://<service>-<hash>.asia-south1.run.app`) as `API_PROXY_URL` below.

## 3. Web on Vercel

1. Vercel → Add New → Project, pick this repository, and set **Root Directory** to `apps/web`.
   `apps/web/vercel.json` sets the install and build commands and the Mumbai region.
2. Environment variables (Production):
   - `NEXT_PUBLIC_API_URL` = `/api/v1`
   - `API_PROXY_URL` = `https://<service>.onrender.com`
   - `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`, `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID`: see step 4. Without
     them the dashboard shows the district grid instead of the map.
3. Deploy, then put the site's address (and any custom domain) into the API's `CORS_ORIGINS`
   on Render, comma-separated, and redeploy the API.

## 4. Google Maps key

In Google Cloud, restrict the browser key by HTTP referrer to the production domain(s) and
`localhost`, and to **Maps JavaScript API** and **Places API (New)** only. Set a billing budget
alert. The README's **Google Maps** section has the full list.

## 5. Check the live site

- Sign in as the admin, open Settings → Users and create the salesmen. Each signs in on their
  phone and installs the app ("Add to Home screen").
- On a phone: Start Day, a visit with a photo, End Day, Submit. The photo should show in the
  admin's Sales team → day view.
- Settings → Audit log shows the admin's and the salesman's actions.
- Supabase → Advisors: no security warnings.

## Secrets and keys

- Rotate anything that was ever pasted into a chat, an email or a ticket: the Supabase secret
  key and the database password of the development project included.
- The service-role/secret key lives only in Render. It must never be set in Vercel or in any
  `NEXT_PUBLIC_` variable.
- To sign everyone out (e.g. after a leaked JWT secret), change `JWT_REFRESH_SECRET` on Render
  and redeploy.

## Known limits

- Requests to the API pass through Vercel's proxy. If a very large bulk-import file fails to
  upload, split it into smaller files.
- Render free instances sleep, so stay on Starter or above.
- The PWA records location only while it is open on screen (SPEC 10). Background tracking needs
  the native app.
